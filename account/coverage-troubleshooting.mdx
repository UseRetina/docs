Retina combines several public data sources because no single provider covers every wallet, chain, protocol, and position type.

## Coverage by portfolio area

| Area | Current sources include |
| --- | --- |
| EVM wallets and DeFi | Zerion and protocol-specific enrichment |
| Solana wallets and DeFi | Helius, Jupiter, TopLedger, Vybe, and Moralis |
| Hyperliquid | Hyperliquid public APIs |
| Polymarket | Polymarket public APIs |
| Yield and maturity | Protocol data, Pendle, and DeFiLlama |
| Prices | CoinGecko, token-market sources, and metals pricing providers |
| Rewards | DropsBot, Merkl, Pendle, and supported protocol sources |
| Risk | Diapleo |

Provider use and fallback order can change as coverage improves.

## Saved and live values

- Snapshot totals use values saved during capture.
- Older snapshots remain frozen.
- The latest Polymarket view can refresh public market data.
- Yield data and watchlist prices can refresh separately.
- Activity is fetched and reconciled around tracked wallets and snapshot intervals.

Check the page label, source field, and freshness message before comparing values.

## A position is missing

1. Confirm the correct public address is tracked.
2. Run the address check from setup.
3. Create or retry the snapshot when the provider is available.
4. Review exclusions and hidden dust.
5. Add a manual position when the holding is private or unsupported.

## A value changed unexpectedly

Open **What Changed** and review wallet activity. For an automatic snapshot, open **Updates**. The review identifies each token or protocol balance, the wallets that changed, and their previous and proposed values. Choose **Looks right** for a change you recognize and **Check again** for a balance that needs a fresh read.

A protocol summary may not have a contract address because the provider reports a combined protocol balance. Retina labels that row with the protocol and shows the contributing wallets instead of presenting it as a token.

Provider errors, token repricing, protocol migrations, missing supplementary data, and real transfers can all change a result. Solana lending totals also changed in September 2026: protocols that were being dropped now report correctly, and loans against unvalued collateral are now excluded. Retina keeps blocking candidates out of saved history until you review them.

## A provider check is delayed or stopped

"Retrying shortly" means Retina is pacing calls before they reach the provider. You can close **Updates** while an automatic retry runs. Retina continues it in the background and refreshes the dashboard notice when the state changes.

A **partial** row means Retina loaded usable wallet data but one or more supplementary provider reads did not finish. The row action changes to **Retry**. During a bulk check, Retina queues that retry behind the current wallet in the same network family.

"TopLedger timed out" means a required Solana verification exceeded Retina's 45-second reliability window. Retina queues one retry instead of saving an incomplete result. An "offline" status is reserved for a provider request that failed rather than merely responding slowly.

"Today's data allowance for this account is used" means the signed-in account reached its plan's provider safety ceiling. The allowance covers setup, automatic captures, and recovery attempts, and resets at midnight UTC. Repeated address checks consume it even when no snapshot is saved.

If a provider remains unavailable after the retry, try later. Remove that wallet only when you intentionally want a snapshot without it.

## A Solana position was left out on purpose

A message beginning **"Partial Solana coverage"** means Retina read the wallet and chose not to count something. The data arrived and was refused, which is different from a provider that failed.

**Borrowing against collateral that could not be valued.** Some principal tokens and senior tranches have no published price. When a provider values a loan's collateral at zero but still reports its debt, counting that debt alone would subtract money you have not lost. Retina leaves the whole loan out and names the protocol. The same applies when reported debt exceeds collateral by more than ten times, which every lending protocol liquidates long before, so the figure is an upstream error rather than a position.

**Liquidity priced without its underlying tokens.** The position is counted and its value is understated.

**Position data is several days old.** Retina reports the age instead of treating a stale figure as current.

**A protocol is active but returned nothing.** A receipt token proves the position exists even though the protocol read came back empty.

These need no action. They explain a total that would otherwise look too low, and they clear once the provider can price the asset.

## APY or maturity is missing

Open the position details to see the available source. Add a manual APY or maturity when you have a reliable value that Retina cannot detect.

## Sign-in or restore is blocked

- Confirm you chose a sign-in method linked to the same account.
- Complete the security check on the sign-in page.
- Use the conflict prompt instead of clearing browser storage.
- Download a backup before replacing a browser portfolio.

Use the **Help** button in Retina when the issue continues. Include the page, wallet family, and visible error. Never send a seed phrase or private key.
